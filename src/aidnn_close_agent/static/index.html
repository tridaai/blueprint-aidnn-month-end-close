Definition governance

Loading the definition registry…

Changing a definition is a governed act, not a file swap. A candidate version's impact is first computed as a dry-run over a signed period — both versions recomputed from that period's stamped sources — and recorded; a named activation then makes the version govern from a stated period, citing the dry-run it relied on. No activation reaches a signed period, and the version governing each run is selected by that rule and printed on the run.

What the verifier enforces

Every figure in a pack is recomputed from the source extracts by an independent code path. A figure that cannot be reproduced blocks the pack, with the variance named — a duplicated journal, an unmatched intercompany leg, a subledger tie-out gap. A pack built from superseded extracts goes stale by its version stamps and cannot be signed. Only a fully verified pack reaches the controller. From the second month on, each pack also carries comparatives cited from the prior period's signed pack — and if that period's sources were restated after sign-off, the restatement is named on the pack and the signature is held until a controller acknowledges it.

A blocked pack has a second honest exit besides fixing the books: a named controller accepts a blocking variance in writing — a disposition — and the close is presented for sign-off with the acceptances on its face, the variances standing exactly as computed. An accepted break is never forgotten: it opens the next period as a named item, is re-tested against the new sources, and blocks again if it is still there.
